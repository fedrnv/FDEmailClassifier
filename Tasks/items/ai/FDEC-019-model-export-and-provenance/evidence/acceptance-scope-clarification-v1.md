# FDEC-019 acceptance interpretation

The immutable AC-01 explicitly specifies local synthetic/non-sensitive fixtures
for GGUF load/round trip and the release-manifest license gate. A complete,
randomly initialized numerical Qwen3 with a nonzero random LoRA adapter can
exercise that original criterion without actual email training or pretrained
tensors. No criterion, dependency, allowed path or task outcome is amended.

The initial readiness commentary demanded actual trained-model conversion. That
was an unnecessarily restrictive executor interpretation, not an accepted task
contract amendment. This append-only clarification and successor readiness keep
the full actual model-conversion/load obligation, exercised on a complete
synthetic model rather than the earlier two-matrix container-only fixture.
Metadata mocks, container checks and a process double alone cannot close AC-01.

Required evidence: real upstream PEFT/GGUF conversion, complete base+adapter and
merged GGUF loading in a locally built pinned llama.cpp runtime, equal numerical
two-token probe, tokenizer/chat metadata, SBOM schema validation, provenance/card
inventory, real fixture release denial, and targeted license/integrity/recovery
tests. Positive license-gate tests use isolated counterfactual legal records and
grant no real rights. The real release registry remains empty/default-deny.

Numerical technical fixtures are not actual email training texts or labels.
No optimizer, model training, actual email-model evaluation, real/private email,
paid resource or public weight/model/tokenizer redistribution is authorized by
this record. FDEC-015/FDEC-016 real-data/training obligations and D003 gate/review
remain separate. The repository policy and both prohibited Codex packs remain
unchanged. No owner permission beyond the existing software-development and
technical-fixture authorization is required for this original acceptance scope.
