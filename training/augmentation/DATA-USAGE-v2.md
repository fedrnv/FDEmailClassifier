# Software fixtures and independent training data: owner clarification

The owner has confirmed that no separate permission for using Codex Output to
train a distributed model is available. The owner explicitly directs continued
generator/training software development and permitted technical testing, with
actual training data obtained independently of OpenAI under documented rights.
This is a development/data-selection instruction, not a new provider permission.

Both `codex-fixture-v1` and `fdec-native-templates-v1`, including generated message
texts and example labels, remain **software_fixture only**. They are not admitted
for actual commercial training or model evaluation. Renaming the source, copying
only its annotations, changing a per-pack purpose list or adding an Apache-2.0
header cannot promote these artifacts. The source-code license and honest
Codex-assisted authorship stay recorded. No real personal mail or personal data
are authorized inputs to these technical fixture generators.

Earlier hash-bound rights assessments and blocker checkpoints remain historical
evidence. Their statement that a native commercial grant was needed before
software acceptance is superseded by the owner's clarified task contract through
append-only FDTasks events. Their denial of training rights is **not** superseded.
Software implementation acceptance no longer claims or requires promotion of
Codex examples into training data. No permission document is being fabricated.

The generator enforces fixture-only treatment for both known pack IDs and
Codex/OpenAI-origin labels even if a per-pack audit is accidentally promoted.
Annotation streams carry explicit data-usage/provenance metadata in addition to
the receipt; copying a canonical-looking label does not establish source rights.
The training-input boundary rejects augmentation receipts and supports only
separately verified independent ingestion in this version.

`independent-training-sources-v1.json` binds the current independent source
selection to its existing legal audit, observations and report. Its production
entry is the exact weijianzhg seed artifact already admitted by FDEC-008 for
specialized email-classifier training/evaluation, with uploader-declared
Anthropic/OpenRouter origin. The original scope, evidence limitations and
redistribution restrictions remain in force. This is not a broader license grant,
a guarantee about every row, or a blanket approval of any external corpus.
Blocked imnim/talby sources and unlisted sources remain rejected.

`training_boundary.assert_training_source` validates the independent-origin
selection and calls the existing current rights guard. `admit_training_run`
then requires an exact FDEC-009 receipt, approved raw-source bytes and the current
normalization implementation. It regenerates the normalized texts and labels
from an in-memory snapshot of the verified source bytes. Updating a file checksum
after injecting Codex labels/text therefore cannot pass. The gate is read-only,
prints no data and does not start training or fetch a corpus.

Consumers should request `include_records=True` and use the returned verified
snapshot rather than rereading mutable message files after admission. Metadata
admission alone is not permission to train: current consent, safe grouped splits,
data quality and later training-task checks still apply. The result explicitly
states that split/consent validation remains required. Additional independent
sources need an actual audit and reviewed source-policy/ingestion support; there
is no runtime origin or rights override in the production interface.

The component can be verified and closed with permitted technical fixtures and
isolated test policies. Such tests do not approve those fixture rows as a real
dataset. Actual model training, dataset redistribution and model publication are
outside FDEC-011 acceptance and retain their separate authorization and evidence
requirements. No training-ready dataset or model quality is claimed here.
